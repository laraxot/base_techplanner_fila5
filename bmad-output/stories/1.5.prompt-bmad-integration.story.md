# 1.5: Prompt BMAD Integration

**Story ID:** 1.5
**Epic:** 1 — Prompt Directory Analysis & Cleanup
**Slug:** prompt-bmad-integration
**Status:** ready-for-dev

> Owned by planning until `done`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **multi-agent system maintainer**,
I want **every prompt to reference its BMAD workflow position and lifecycle**,
so that **agents know which planning artifact the prompt supports and what stage of work it serves**.

## Acceptance Criteria

1. Every prompt has `bmad_workflow` field in YAML front matter: one of `analysis | planning | solutioning | implementation | review`.
2. Every prompt has `bmad_artifacts` field: array of paths to `bmad-output/` files this prompt supports.
3. Every prompt has `bmad_stages` field: array of stage names from the BMAD lifecycle.
4. A `bmad-position.md` index file exists at `bashscripts/docs/prompts/_INDEX.md` mapping each prompt to its BMAD workflow.
5. Backlinks from `bmad-output/` to relevant prompts documented in `bmad-output/INDEX.md`.

## Tasks / Subtasks

- [ ] Define BMAD workflow mapping (AC: #1, #2, #3)
  - [ ] For each prompt, identify: which BMAD workflow (analysis/planning/solutioning/implementation/review)
  - [ ] Identify: which `bmad-output/` artifacts (e.g. `SPEC.md`, `epics.md`, `stories/1.1.*.md`)
  - [ ] Identify: which BMAD stages (e.g. `drafting`, `ready-for-dev`, `in-progress`)
- [ ] Add BMAD fields to front matter (AC: #1, #2, #3)
  - [ ] `bmad_workflow: <workflow>`
  - [ ] `bmad_artifacts: [<path>, ...]`
  - [ ] `bmad_stages: [<stage>, ...]`
- [ ] Create `bashscripts/docs/prompts/_INDEX.md` (AC: #4)
  - [ ] Table: prompt | BMAD workflow | artifacts | stages
  - [ ] Group by workflow
- [ ] Create `bmad-output/INDEX.md` backlink index (AC: #5)
  - [ ] For each artifact, list which prompts reference it
  - [ ] Reverse mapping
- [ ] Validate BMAD references (AC: #1, #2)
  - [ ] All listed `bmad-output/` paths exist
  - [ ] All workflow values in allowed enum

## Dev Notes

- BMAD workflow enum [Source: .opencode/skills/bmad-help/SKILL.md#workflows]:
  - `analysis` — product brief, research, brainstorm
  - `planning` — spec, PRD, sprint planning
  - `solutioning` — architecture, UX, epics, stories
  - `implementation` — direct dev work, code, tests
  - `review` — investigation, audit, correct-course
- BMAD stage lifecycle [Source: bmad-output/project-context.md#lifecycle]: `backlog → ready-for-dev → in-progress → review → done`
- Front matter schema v2 with BMAD extensions [Source: 1.2.prompt-frontmatter-standardization]
- Backlinks are bidirectional: prompt → artifact AND artifact → prompt
- [Inference] Most operational prompts (e.g. `03-quality-gates.md`) belong to `implementation`; design prompts belong to `solutioning`

## Testing

- **Approach:** static analysis (YAML parse + path existence check)
- **Key scenarios:** all BMAD references valid
- **Per-AC verification:**
  - AC #1 → `bmad_workflow` value in allowed enum
  - AC #2 → all paths in `bmad_artifacts` exist (`test -f`)
  - AC #3 → all stages in allowed lifecycle enum
  - AC #4 → `_INDEX.md` exists and lists all prompts
  - AC #5 → `bmad-output/INDEX.md` exists with reverse mapping
- **Edge cases:** prompts that span multiple workflows (use primary workflow + note in description), artifacts that span multiple prompts (N-to-M is normal)
