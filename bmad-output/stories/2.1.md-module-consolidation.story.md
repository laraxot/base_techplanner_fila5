# 2.1: Module Documentation Consolidation

**Story ID:** 2.1
**Epic:** 2 — Module Documentation Standardization
**Slug:** module-documentation-consolidation
**Status:** backlog

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **maintainer / future developer**,
I want to consolidate module documentation so that each module root has at most 6 markdown files,
so that the codebase stays navigable and maintainable.

## Acceptance Criteria

1. Every module root directory has at most 6 .md files
2. Critical docs (README.md, CHANGELOG.md) preserved in root
3. Philosophy/analysis docs consolidated in `docs/` folder with proper naming
4. File naming convention: kebab-case, no dates, no special characters
5. Cross-references updated to reflect new file locations

## Tasks / Subtasks

- [ ] Identify modules exceeding 6 .md files in root (Xot needs consolidation)
  - [ ] Analyze purpose of each .md file
  - [ ] Group into logical categories (architecture, rules, guidance, etc.)
- [ ] Create consolidated docs in `docs/` folder for each category
  - [ ] `docs/architecture-guidelines.md` - architettura e pattern
  - [ ] `docs/critical-rules.md` - regole obbligatorie
  - [ ] `docs/best-practices.md` - consigli e best practices
  - [ ] `docs/false-friends.md` - errori comuni
  - [ ] `docs/philosophy.md` - filosofia del modulo
  - [ ] `docs/README.md` or appropriate index
- [ ] Remove redundant files from root folders
- [ ] Update cross-references in all .md files
- [ ] Verify no broken links

## Dev Notes

- Module roots with >6 .md: Xot (129 files - CRITICAL). Needs triage.
- Standard root files to keep: README.md, CHANGELOG.md, LICENSE.md (if applicable)
- For Xot specifically:

- Keep `README.md` in root as primary entry point
