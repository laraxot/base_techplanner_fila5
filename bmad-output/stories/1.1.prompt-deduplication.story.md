# 1.1: Prompt Deduplication

**Story ID:** 1.1
**Epic:** 1 — Prompt Directory Analysis & Cleanup
**Slug:** prompt-deduplication
**Status:** ready-for-dev

> Owned by planning until `done`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **documentation maintainer**,
I want **duplicate prompt files identified and removed**,
so that **the directory has a single source of truth per concept and maintenance is unambiguous**.

## Acceptance Criteria

1. Content-hash analysis run on all `.md` files in `bashscripts/docs/prompts/`.
2. Duplicate clusters listed in a report at `bmad-output/decision-log.md` with: hash, files in cluster, recommended canonical file.
3. True duplicates removed via `git mv` (preserves history). Aliases kept as one-line `redirect.md` files linking to canonical version.
4. Zero content-duplicate files remain in `bashscripts/docs/prompts/` (verified by re-running content-hash analysis).
5. Git history preserved (no force-push, no destructive operations).

## Tasks / Subtasks

- [ ] Run content-hash dedup analysis on all .md files (AC: #1)
  - [ ] Use `sha256sum bashscripts/docs/prompts/*.md | sort`
  - [ ] Group by hash, list clusters
- [ ] Add duplicate report to `bmad-output/decision-log.md` (AC: #2)
  - [ ] Hash, file list, recommended canonical per cluster
  - [ ] Rationale: which version is most complete / most recent
- [ ] Remove true duplicates via `git mv` (AC: #3, #5)
  - [ ] Canonical stays at original path
  - [ ] Duplicates → one-line alias file with redirect link
  - [ ] Front matter on alias: `redirect_from: <old-path>`
- [ ] Verify zero duplicates remain (AC: #4)
  - [ ] Re-run hash analysis
  - [ ] Confirm 0 clusters with size > 1

## Dev Notes

- Scope target: `bashscripts/docs/prompts/**/*.md` (42 files currently)
- Known duplicates to investigate:
  - `start.md`, `START.md`, `start_optimized.md` (if they exist)
  - Any files sharing identical content
- Use `git mv` not `rm` + `git add` to preserve history [Source: docs/wiki/git/forward-only-strategy.md]
- BMAD skill `bmad-prd` for tracking rationale
- Decision-log append entry required for each cluster resolved [Source: bmad-output/decision-log.md]
- [Inference] Likely 3-5 duplicate clusters; canonical should be the one with most complete YAML front matter

## Testing

- **Approach:** static analysis (file hash + git log inspection)
- **Key scenarios:** all duplicates removed, history preserved
- **Per-AC verification:**
  - AC #1 → `sha256sum *.md | awk '{print $1}' | sort | uniq -d` returns empty
  - AC #2 → `bmad-output/decision-log.md` contains duplicate report
  - AC #3 → `git log --follow <alias-path>` shows history
  - AC #4 → re-run hash analysis, 0 duplicates
  - AC #5 → `git log --all --oneline | head` shows preserved history
- **Edge cases:** near-duplicates (different by 1-2 lines) flagged but not auto-merged; only exact-hash duplicates auto-resolved
