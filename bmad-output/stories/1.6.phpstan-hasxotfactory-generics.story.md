# 1.6: PHPStan L10 HasXotFactory Generic Type Annotation

**Story ID:** 1.6
**Epic:** 1 — Prompt Directory Analysis & Cleanup (ext.)
**Slug:** phpstan-hasxotfactory-generics
**Status:** ready-for-dev

## Story

As a **PHPStan L10 maintainer**,
I want **all models using HasXotFactory trait to specify the generic Factory type**,
so that **PHPStan reports zero `missingType.generics` errors and Factory<static> contract is honored**.

## Acceptance Criteria

1. Zero `missingType.generics` errors related to `HasXotFactory<TFactory>` trait usage.
2. Zero `class.notFound` errors referencing Factory classes in trait `@use` annotations.
3. Affected models: User (5), Xot (3), Job (1), Lang (1), Tenant (3), Activity (3), Media (2), Geo (3).
4. Each `use HasXotFactory;` preceded by PHPDoc `/** @use HasXotFactory<FactoryClassName> */` line.
5. PHPStan L10: 0 errors after fix.

## Tasks / Subtasks

- [ ] Audit each model and identify correct Factory class name (AC: #3)
- [ ] Add `/** @use HasXotFactory<FactoryClass> */` above `use HasXotFactory;` line (AC: #1, #4)
- [ ] Verify no class-notFound errors (AC: #2)
- [ ] Run PHPStan L10 (AC: #5)

## Dev Notes

- `HasXotFactory` trait is now generic with `@template TFactory of Factory<*>` [Source: laravel/Modules/Xot/app/Models/Traits/HasXotFactory.php]
- Models must specify the Factory class that produces them
- Convention: `use Illuminate\Database\Eloquent\Factories\Factory;` already imported in most files
- Format: `/** @use HasXotFactory<\Modules\X\Database\Factories\XFactory> */` on line above trait use
- [Source: docs/wiki/phpstan/bootstrap-learnings.md#missing-iterable-value-types]
