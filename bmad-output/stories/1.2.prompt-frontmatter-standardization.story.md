# 1.2: Prompt Frontmatter Standardization

**Story ID:** 1.2
**Epic:** 1 — Prompt Directory Analysis & Cleanup
**Slug:** prompt-frontmatter-standardization
**Status:** ready-for-dev

> Owned by planning until `done`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **documentation maintainer and AI agent**,
I want **all prompts to have consistent YAML front matter with required fields**,
so that **agents can index, route, and discover prompts reliably without parsing free text**.

## Acceptance Criteria

1. All `.md` files in `bashscripts/docs/prompts/` have YAML front matter delimited by `---`.
2. Required fields present in every file: `id`, `slug`, `title`, `description`, `document_type`, `category`, `status`, `version`, `language`, `tags`.
3. Valid YAML syntax (parsable by Python `yaml.safe_load` with 0 errors).
4. `document_type` is one of: `prompt | guide | reference | audit | recipe`.
5. `category` is one of: `architecture | quality | workflow | testing | documentation | operations | analysis`.

## Tasks / Subtasks

- [ ] Audit existing front matter (AC: #1)
  - [ ] Identify which files have no front matter
  - [ ] Identify which files have partial front matter
- [ ] Define front matter template at `bashscripts/docs/prompts/_TEMPLATE.md` (AC: #2, #4, #5)
  - [ ] All 10 required fields with example values
  - [ ] Document allowed values for `document_type` and `category`
- [ ] Apply front matter to all files missing it (AC: #1, #2, #3)
  - [ ] Infer values from file content (e.g. `01-architecture-patterns.md` → `category: architecture`)
  - [ ] Slug = filename without `.md`
  - [ ] Tags = 3-5 keywords from content
- [ ] Validate YAML syntax (AC: #3)
  - [ ] `python3 -c "import yaml; yaml.safe_load(open('file.md'))"` for each
  - [ ] Zero parse errors

## Dev Notes

- YAML front matter convention: matches `docs/wiki/concepts/obsidian-flavored-markdown.md` [Source: docs/wiki/concepts/obsidian-flavored-markdown.md]
- Field semantics:
  - `id`: stable identifier (`prompt-001-architecture-patterns`)
  - `slug`: kebab-case filename without extension
  - `title`: human-readable display
  - `document_type`: enum see AC #4
  - `status`: `draft | stable | deprecated`
  - `version`: semver string
  - `language`: ISO 639-1 (`en`, `it`)
  - `tags`: array, 3-5 items
- Pattern reference: see `laravel/Modules/Cms/docs/PHILOSOPHY.md` for canonical structure [Source: laravel/Modules/Cms/docs/PHILOSOPHY.md#front-matter]
- [Inference] ~30-40% of files likely have partial/missing front matter

## Testing

- **Edge cases:** empty files, files with only front matter, files with multi-doc YAML
