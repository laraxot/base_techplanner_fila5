# Story 8.6 — Domain enums over model constants

## Problem

Employee models expose status/type vocabularies as string constants. This
duplicates the domain vocabulary, weakens typing, and contributes to PHPStan
constant-type noise.

## Decision

Replace domain constants with backed enums and use Enum::CASE->value at
boundaries that persist strings. Keep technical constants (URLs, cache keys,
limits, paths and static configuration) as constants.

## Acceptance criteria

- [x] Absence request statuses and types have dedicated backed enums.
- [x] Time-entry statuses have a dedicated backed enum.
- [x] Employee production code and tests no longer reference the removed model
      domain constants.
- [x] Existing persisted string values and query behavior remain unchanged.
- [x] PHPStan targeted analysis and focused Pest tests pass.

## Scope

- `laravel/Modules/Employee/app/Enums/`
- `laravel/Modules/Employee/app/Models/`
- Employee actions, resources, factories and unit tests that reference the
  removed constants.

## Learning

Do not convert technical constants to enums: an endpoint or cache duration is
not a finite domain vocabulary.
