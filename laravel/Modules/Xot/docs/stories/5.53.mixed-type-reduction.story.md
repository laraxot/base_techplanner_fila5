# Story 5.53 — Riduzione `mixed` nei Modules

## Contesto

Censimento 2026-09-03: 217 file PHP (esclusi test/build/vendor) usano `mixed`
come tipo nativo (`: mixed`, `mixed $x`). `mixed` disattiva l'analisi statica
nel punto d'uso e propaga `mixed` a valle: PHPStan L10 lo segnala come
technical debt.

## Principio (SSoT)

`mixed` è **legittimo solo al boundary**: input esterni non tipizzabili
(request, JSON, config, cast Eloquent, callable generici da framework).
Le `Safe*CastAction` di Xot esistono esattamente per convertire quel `mixed`
in tipi sicuri: **loro devono accettare `mixed`** — è il loro contratto.

`mixed` è **pigro** (da sostituire) quando:
1. Il valore ha già un tipo noto nel flusso (sostituire col tipo reale).
2. È un union esprimibile: `int|string`, `array|Collection`, ecc.
3. È un template Filament/Eloquent esprimibile con generics in PHPDoc.
4. È un return che il chiamante deve ri-castare subito (code smell).

## Acceptance Criteria

- [ ] AC1 — Triage completo: ogni file del censimento marcato KEEP (boundary)
      o FIX (sostituibile), con motivo.
- [ ] AC2 — Tutti i file FIX modificati: `mixed` → tipo adeguato
      (union, generics, tipo concreto o Safe*CastAction al boundary).
- [ ] AC3 — Gate completo dopo OGNI file: PHPStan (max) + phpmd + phpinsights
      + Pest pertinente (`./tools/post-edit-php.sh`).
- [ ] AC4 — Coverage Pest non in regressione: test aggiunti/migliorati
      per i file toccati privi di test.
- [ ] AC5 — Baseline PHPStan non peggiorata: `phpstan analyse Modules` a fine
      story con errori <= baseline di partenza.
- [ ] AC6 — Regola distillata nel second brain (wiki rules) + memoria.

## Rischi

- Cambiare firma pubblica di metodi usati da altri moduli → rompere chiamanti:
  verificare usi con grep prima di ogni cambio firma.
- Filament/Eloquent richiedono firme compatibili con i parent: dove il parent
  dichiara `mixed`, il figlio NON può restringere (LSP) → KEEP con PHPDoc
  più preciso (`@param`).
