# XOT-5.43 — `phpstan analyse Modules` verde + ide-helper

## Story

Come **tech lead quality**,
voglio che `cd laravel && ./vendor/bin/phpstan analyse Modules` bootstrappi e resti a **0 errori**,
e che **ide-helper** rafforzi i contratti Eloquent/Facade usati da Larastan,
così che il gate statico misuri debito reale e non parse error da marker di merge.

## Perché (business logic)

1. **PHPStan non parte** se Autoload carica un file con `<<<<<<<`: oggi `XotData.php` blocca `CmsServiceProvider` → bootstrap Larastan fallisce prima di qualsiasi finding tipizzato.
2. Marker residui **avvelenano** second brain e test: due verità nello stesso file.
3. **ide-helper** elimina falsi positivi su magic property/relation — stesso percorso di [laravel-ide-helper-property-exists](../laravel-ide-helper-property-exists.md).

## Evidenza di partenza (2026-08-27)

```text
./vendor/bin/phpstan analyse Modules
→ Application bootstrap failed
→ syntax error, unexpected token "<<" in Modules/Xot/app/Datas/XotData.php:361
```

Censimento marker in `laravel/Modules` (PHP): ~295 file (`app` ~101, `tests` ~164, other ~29).

## Acceptance Criteria

1. Zero `^<<<<<<<` / `^=======` / `^>>>>>>>` in `laravel/Modules/**/*.php` (app, tests, migrations, lang PHP).
2. `php artisan about` e bootstrap Larastan senza fatal/parse.
3. `./vendor/bin/phpstan analyse Modules --memory-limit=-1 --no-progress` → **[OK] No errors**.
4. `php artisan ide-helper:generate` + `ide-helper:models --nowrite` (o `--write` dove governance modulo lo consente) completano senza fatal; `_ide_helper*.php` aggiornati.
5. Dev Agent Record + write-back docs modulo owner toccati; wiki log se policy.

## Strategia risoluzione conflitti (KISS + type safety)

Per ogni hunk: tenere il lato **non vuoto**; a parità, il lato con più `Assert::` / `@phpstan` / type hints (allineato a PHPStan max). Nesting: risolvere dall’interno. File ancora invalidi dopo resolve → ricostruire in avanti studiando history clean (`git show` / `git log -S`), senza `restore`/`checkout` file.
