# Story UI-7.2: contratti bootstrap test e sicurezza Blade

## Story

Come owner UI, voglio eliminare API PHPUnit interne e chiamate Pest dinamiche dal bootstrap
e dal test XSS, così che tutti gli shard consumer partano da un harness pubblico e tipizzato.

## Baseline e cause radice

**3 findings / 2 file**: 2 `method.internal` in `TestCase` e 1 `method.notFound` nel test
Blade. È il gate sorgente del dependency cone perché ogni test UI usa il TestCase modulo.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. TestCase usa soltanto API Pest 5/PHPUnit pubbliche compatibili con Xot.
2. Il test XSS usa un'asserzione pubblica e verifica ancora l'escaping Blade osservabile.
3. Entrambi i file sono PHPStan-green e il Pest mirato passa senza skip o tautologie.
4. Nessun ignore, baseline, `.neon`, Service o helper proxy viene aggiunto.

## Dev Agent Record

### Implementazione

- Rimossi i due accessi a `PHPUnit\Framework\TestCase::groups()`, API `@internal`.
  Quando il DB UI non è disponibile, il bootstrap usa il percorso pubblico del test per
  lasciare eseguibili gli Unit; non esistono consumer `ui-db` nel census corrente.
- Rimossa la chiamata dinamica `test()->markTestSkipped()` dal test Blade: il template
  esiste nel modulo e la sua presenza/rendering è ora un contratto esplicito che fallisce
  semanticamente se il file viene rimosso.
