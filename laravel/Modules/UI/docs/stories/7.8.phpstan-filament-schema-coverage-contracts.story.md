# Story UI-7.8: contratti Filament schema coverage

## Story

Come owner UI, voglio tipizzare i payload schema Filament, così che le callback ricevano
record, Get/Set e state coerenti con l'esecuzione reale.

## Baseline e cause radice

**19 findings / 1 file**: 16 argomenti incompatibili, 2 assertion determinate e un iterable
senza value type; il problema è un harness di valutazione callback troppo generico.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Ogni callback schema viene invocata con arity e tipi Filament reali.
2. Array schema e risultati hanno value type/shape minimi espliciti.
3. Assertion determinate sono sostituite da proprietà/rendering osservabili.
4. Il file è PHPStan-green e Pest passa senza skip/tautologie.
5. Nessuna suppression, baseline, `.neon`, proxy o cast cosmetico viene aggiunto.
