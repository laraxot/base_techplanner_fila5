# 5.12: Regressione dei marker di conflitto nel modulo UI

**Story ID:** 5.12
**Epic:** 5 — Code Quality & Infrastructure
**Status:** done
**Created:** 2026-08-27
**Precedente:** [5.8 merge-conflict-markers-cleanup](5.8.merge-conflict-markers-cleanup.story.md) — stessa causa, chiusa il 18 agosto 2026 e **rientrata**

## Story

Come **agente che deve verificare il proprio lavoro con PHPStan**,
voglio **che nessun file del modulo `UI` contenga marker di conflitto git**,
così **`analyse Modules` misura il codice invece di fermarsi sui `phpstan.parse`, e
`git status` torna a funzionare nel repo del modulo**.

La 5.8 aveva chiuso lo stesso problema il 18 agosto limitandosi a `Modules/**/*.php`.
Il 27 agosto alle 09:12:51 i marker sono rientrati su **316 file**, di cui 292 `.md`,
20 `.php`, 2 `.gitignore`, 1 `.json` e 1 `.gitattributes`. Il `.gitattributes` rotto
faceva fallire ogni comando git nel modulo con
`laraxot/dev is not a valid attribute name: .gitattributes:22`.

## Acceptance Criteria

1. `grep -rIl -E '^<{7} |^>{7} |^={7}$'` non restituisce nulla in tutto il repository, esclusi `.git/` e l'allowlist.
2. `php -l` passa su tutti i file `.php` toccati.
3. Il diff è di sola rimozione: nessuna riga di contenuto persa. `git diff -U0 | grep -E '^\+[^+]'` vuoto.
4. Dove entrambi i lati del conflitto sono pieni, la scelta è motivata e verificata da uno strumento, non dalla posizione nel diff.
5. `git status` torna a funzionare nel repo `module_ui_fila5`.
6. `phpstan analyse Modules/UI` non riporta errori nei file toccati.
7. PHPMD e PHPInsights non riportano nuove segnalazioni sui file toccati.

## Verifiche eseguite

- `git diff -U0 | grep -E '^\+[^+]'` → vuoto. 1.438 righe rimosse, tutte marker o righe bianche.
- `php -l` su tutti i `.php` toccati → 0 errori.
