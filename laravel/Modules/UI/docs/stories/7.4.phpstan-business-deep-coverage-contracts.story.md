# Story UI-7.4: contratti business e deep coverage

## Story

Come owner UI, voglio che i test business/deep passino input conformi alle API reali,
così che la coverage convalidi boundary UI e non payload ambigui.

## Baseline e cause radice

**20 findings / 2 file**: 18 `argument.type` e 2 iterable senza value type, concentrati
in helper Reflection/closure e payload schema non ristretti.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Helper e callback ricevono parametri compatibili con le firme production reali.
2. Array e iterable di schema dichiarano shape/value type minimi verificabili.
3. I test mantengono asserzioni su output ed effetti osservabili, senza catch onnivori.
4. Entrambi i file sono PHPStan-green e Pest mirato passa senza skip/tautologie.
5. Nessuna suppression, baseline, `.neon`, Service o cast cosmetico viene aggiunto.
