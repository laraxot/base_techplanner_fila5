# Story UI-7.13: riduzione uso di mixed dove il tipo e' noto

## Story

Come owner UI, voglio sostituire `mixed` con un tipo piu' preciso ovunque il valore reale
sia deducibile con certezza dal codice circostante, cosi' che il modulo resti PHPStan-green
e i contratti dei componenti siano piu' leggibili, senza inseguire una copertura al 100%
(convenzione "dove possibile").

## Baseline

`grep -rnE '\bmixed\b' Modules/UI --include="*.php"` (esclusi i test): **36 file, 103
occorrenze**. La maggioranza sono `mixed` legittimi (contratti Filament/vendor tipizzati
`mixed` a monte, payload JSON/config genuinamente eterogenei, `LocationSelector.php` e
`InteractiveMap.php` sotto lock attivo `docs/chat/ui-geo-boundary-lock.md`).

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Ogni sostituzione di `mixed` e' giustificata dal codice circostante (uso di
   `array_keys()`, `is_*`/`instanceof`, o firma di libreria) — nessun `@var` di comodo per
   forzare PHPStan.
2. Il conteggio errori PHPStan di `Modules/UI` (`--no-progress --error-format=table`) non
   aumenta rispetto alla baseline pre-edit.
3. I contratti vendor tipizzati `mixed` (closure Filament, `ValidationRule::validate`) e i
   payload genuinamente polimorfi restano `mixed`, documentati come tali.
4. `LocationSelector.php` e `InteractiveMap.php` non vengono toccati (lock geo attivo).
5. Nessun ignore, baseline `.neon`, Service, o cast silenzioso viene introdotto.

## Tasks / Subtasks

<!-- LOCKED. External dev tools must not edit Tasks / Subtasks. -->

- [x] Censire tutte le occorrenze di `mixed` in `Modules/UI/app` (native + docblock),
      ordinate per file con meno occorrenze. (AC: #1)
- [x] Per ogni file, leggere il corpo della funzione/closure e classificare: vendor
      contract (leave), payload polimorfo (leave), tipo deducibile (fix). (AC: #1, #3)
- [x] Applicare le sostituzioni a basso rischio individuate: chiavi array (`int|string`
      invece di `mixed`) e un docblock `array<array-key, mixed>` al posto di
      `array<mixed, mixed>`. (AC: #1)
- [x] Rieseguire PHPStan su `Modules/UI` e confermare nessuna regressione. (AC: #2)
- [x] Aggiornare `docs/coverage.md` con sezione datata ed esito onesto Pest/PHPMD.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- [Source: bashscripts/ai/wiki/rules/no-services-rule.md] Nessuna nuova classe `*Service`
  introdotta; tutte le modifiche sono state chirurgiche su componenti Filament esistenti.
- [Inference] Gli array PHP hanno chiavi sempre `int|string` (`array-key`): un parametro
  `mixed $key` alimentato da `array_keys()` e' sempre restringibile senza rischio, perche'
  il runtime type e' garantito dal linguaggio, non da un'assunzione sul dominio.
- [Inference] I valori delle stesse mappe (`array_values($states)`) restano `mixed`
  perche' il contenuto (stato Filament, enum, dato di modello) e' genuinamente eterogeneo:
  narrowing qui sarebbe un `@var` di comodo, non un fatto verificato — vietato dalla
  guardia "var-override-before-git-log-check".
